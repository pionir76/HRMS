## 남은 작업 요약

### 사양 결정이 먼저 필요한 것

- [ ] **운영 상태가 아닌 장비의 운전일지·점검일지** (2026-09-17 사용자: 추후 결정). 운영이 아닌 장비는 수집하지 않는데, 운전일지 자동채움은 아직 옛 기준(`OperationAutoFillService.NonOperationalStatuses` = 미운영/철거/사용중지)이라 **수리중·점검중·철거예정·기타 장비가 멈춘 값으로 채워질 수 있다**(수집을 멈춘 압축기의 통신 상태가 마지막 값 `연결됨`으로 굳어 조건을 통과함). 점검일지 자동 이어채우기도 장비 상태를 보지 않는다. 사양 결정 시 두 서비스를 같이 맞춘다
- [ ] **트렌드 보존 정책** — 실측 110바이트/행 × 246대 × 1,440분 = 하루 약 37MB, 1년 약 13.4GB. 정리 코드가 없어 디스크가 차면 수집·일지 저장이 동시에 멈춘다. 보관 기간(법정 요구 확인 필요)을 정하고 일 1회 삭제 배치를 추가한다
- [ ] **DB 백업** — `pg_dump` 일 1회 + 보관 N일, 결과를 `GET /api/system/status`의 `databaseBackup`(현재 항상 `null`)에 채운다. 백업 위치(다른 드라이브/NAS)와 주기 결정 필요
- [ ] **테스트 서버 노출 대비** — 납품 과정이 개발 PC → **회사 고정 IP 테스트 서버(`59.16.212.237`, 인터넷 노출, 발주처 외부 테스트)** → 남양연구소 폐쇄망 납품이다(2026-10-02 확인). 운영(현장)은 폐쇄망이라 HTTPS 없이 가는 전제(2026-09-28)가 그대로 유효하고, 인터넷 노출은 테스트 기간 한정이다. 그 기간은 DB 포트(5432) 차단 + 80번 접속을 현대·회사 IP로 제한 + 강한 비밀번호로 대신한다(setup.md 9.2·11.2). 현대 측 공인 IP를 받으면 IP 제한을 적용한다
