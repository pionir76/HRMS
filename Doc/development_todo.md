## 2단계. 통신 및 수집 기능 개발

- [ ] 압축기별 TCP 연결 관리자 (연결 생성/해제/재사용) — (연결을 유지·재사용하지 않고, 폴링 사이클마다 새로 연결하고 끊는 방식으로 단순화. 임베디드 장비 재연결 부담 우려가 있어 추후 실장비로 장시간 검증 예정)
- [x] 프로토콜 파서 구현 (`PcLinkClient`, 체크섬 검증, 16비트 2의 보수 파싱)
- [x] 압축기별 독립 비동기 수집 루프 (`CompressorPollingService`, 3초 주기 — 계획한 1~2초에서 임베디드 장비 부담을 고려해 조정, `Task.WhenAll`로 압축기 간 장애 격리)
- [x] 응답 타임아웃 처리 (`PcLinkClient` 연결/응답 각각 3초 타임아웃) — (자동 재접속 로직은 별도로 없음: 매 사이클 새로 연결하는 구조라 "재접속"이라는 별도 개념 자체가 불필요)
- [x] 실시간 최신값 저장소 — (메모리 캐시가 아니라 DB 테이블 `CompressorSensorCurrent`로 구현. UPSERT로 압축기당 채널 7행 고정 유지)
- [x] 압축기별 통신 상태 관리 (연결됨/끊김/재접속중 상태 머신)
- [x] 장비 운영상태(미운영/철거/사용중지)에 따른 수집 대상 제외 로직
- [x] 통신 장애 이벤트 로그 기록 — (계획과 다름: 원시 `CommunicationStatus` 전이가 아니라, 30초 디바운스를 거친 `HasCommunicationAlarm`이 켜지는 순간만 `EventLog`(Communication 카테고리)에 기록. 복구는 기록 안 함 — 사용자 결정)
- [ ] 디버그 모드 원시 송수신 패킷 로깅 옵션 — `PcLinkClient`가 raw 문자열을 반환하지만 폴링 서비스에서 버려짐(미사용)

## 3단계. 데이터 처리 기능 개발

- [x] 1분 단위 데이터 집계 스케줄러 (`TrendRecordingService`, 정각 기준 재계산 방식, 오차 누적 없음)
- [x] 이력 데이터 저장 로직 (7채널 raw값 + 운전상태 + 경보상태 + 통신상태)
- [x] 채널별 경보 판정 엔진 (`AlarmEvaluator`)
    - [x] 상한/하한 범위 판정 (raw int16 스케일)
    - [x] 경보 발생 지연시간 처리 (`AlarmDelaySeconds`)
    - [x] 경보 해제 지연시간 처리 (`AlarmClearDelaySeconds`)
    - [ ] 히스테리시스 적용 — (사양에서 제외하기로 확정. 경계값 근처에서 상태가 자주 바뀔 수 있음을 감수하는 의도된 단순화)
    - [x] 경보 상태 머신 — (정상/경보발생대기/경보발생/정상복귀대기/경보비활성화 5단계. "확인"·"해제"는 사양에서 제외하기로 확정 — 사용자 확인 없이 값이 정상으로 돌아오면 자동 해제)
    - [x] 채널 단위 경보 on/off 기능 (`AlarmEnabled`, 압축기 단위가 아니라 채널 단위로 세분화)
- [x] 통신 장애 경보 판정 (`Compressor.HasCommunicationAlarm`) — 채널값 기준 `AlarmStatus`와는 완전히 별도 관리. 끊긴 지속시간이 30초(디바운스용 통신 모듈 공통값, 압축기별 설정 아님) 이상이면 켜짐
- [x] 운전/정지 상태 판정 로직 (`EquipmentStatusAggregator.IsRunning`)
    - [x] 전류값(CH07) 기준 임계값 비교 (raw 스케일)
    - [ ] 히스테리시스 적용 — 미구현
    - [ ] 상태 확정을 위한 지속시간 로직 — 미구현(매 사이클 즉시 반영)
    - [ ] 운전시작/정지 시각 기록 — 별도 이벤트 기록 없음(트렌드 스냅샷의 `IsRunning`으로만 매분 흔적이 남음)
- [ ] 비상정지 처리 파이프라인 — 전체 미착수
    - [ ] 사용자 권한 확인 — (역할 5종 체계는 구축됨, 비상정지를 어느 역할에 줄지는 미정)
    - [ ] 대상 장비/압축기/현재상태 확인
    - [ ] 재확인 절차 처리
    - [ ] TCP 쓰기 명령 전송 및 응답 확인
    - [ ] 중복 실행 방지 (락/세마포어)
    - [ ] 통신 장애 상태에서 명령 제한/경고
    - [ ] 처리결과 저장 및 이벤트 로그 기록 (EmergencyStop 카테고리)
- [x] 이벤트 로그 공통 기록 모듈 (`EventLogger.LogAsync`)

## 4단계. API 및 관리 기능 개발

- [x] 인증 API (로그인/로그아웃, 비밀번호는 `PasswordHasher<User>`로 암호화 저장) — (계정 잠금은 20명 규모에 비해 과하다고 판단해 구현하지 않기로 확정)
- [x] 사용자 역할 관리 — (당초 계획한 "조회/운영/관리자" 3단계 대신, 실제 조직 구조에 맞춘 5개 역할로 재설계: 시스템관리자/안전관리총괄자/안전관리책임자/안전관리원/일반관리자. `시스템관리자`만 전체 권한, 나머지 4개는 현재 조회만 가능하고 권한 차이 없음. 비상정지는 사용자별 플래그가 아니라 향후 역할 기준으로 일괄 부여 예정 — 어느 역할인지는 미정)
- [x] 사용자 인적사항 관리 — 계획에 없었으나 추가됨: 성명/직책/법정교육일/차기교육일/부서/대직자, 담당장비 다대다(`UserEquipment`). 아직 이 정보를 다루는 API는 없음(DB 모델만 존재)
- [ ] 장비 관리 API (CRUD, 운영상태 변경) — 조회(GET)만 있고 등록/수정/삭제는 없음
- [ ] 압축기 관리 API (CRUD) — 조회(GET)만 있음
- [x] 센서 채널 설정 조회 API (`GET /api/compressors/{id}/channel-settings`) — (조회만 가능, 설정 변경 API는 아직 없음)
- [x] 실시간 데이터 조회 API (`GET /api/compressors/{id}/channels`)
- [x] 트렌드/이력 조회 API (`GET /api/compressors/{id}/trend`)
- [ ] 경보 이력 조회 API — 발생/해제 이력 자체는 `EventLog`(Alarm 카테고리)에 쌓이고 있으나, 이를 조회하는 API는 아직 없음 — (경보 확인 기능은 사양에서 제외하기로 확정)
- [ ] 경보 기준값/지연시간 설정 API — 미구현(현재는 DB 직접 수정만 가능) — (히스테리시스는 사양 제외 확정)
- [ ] 비상정지 API — 미구현
- [x] 이벤트 로그 조회 API (`GET /api/events?since=&take=`) — 프론트 실시간 현황 화면용
- [x] 실시간 현황 집계 API (`GET /api/summary`) — 전체/운전중 장비 수, 전체/통신불량 압축기 수
- [ ] 보고서 / 점검일지 / 운영일지 / 게시판 API — 전부 미구현
- [ ] 첨부파일 업로드/다운로드 처리 — 미구현
- [x] 가동률 조회 API — 계획에 없었으나 추가됨: `GET /api/equipments/{id}/utilization?from=&to=`
