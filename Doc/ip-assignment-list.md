# 압축기 IP 신규 할당 대상

현재 장비 자료(`Infrastructure/Compressors.csv`)에 **IP가 없는 압축기 23대(장비 16대)** 목록이다(2026-10-14 기준).
이 압축기들은 현장에서 TLC의 **MAC 주소를 수집한 뒤 IP를 새로 할당받아야** 한다.

IP가 없는 동안에는 다음과 같이 동작한다.

- **데이터를 수집하지 않는다.** 실제 통신 모드에서는 폴링 대상에서 빠진다.
- **통신 상태가 갱신되지 않는다.** 마지막 값이 그대로 남으므로 화면 표시를 믿을 수 없다.
- **비상정지를 걸 수 없다.** 1번 압축기에 IP가 없으면 비상정지는 실패하는 사양이다.

> 다른 장비는 LG 배터리(10.90.87.217 공유)를 빼면 **압축기마다 TLC가 따로 있고 IP도 따로 쓴다.** 그래서 MAC과 IP도 압축기마다 하나씩 받는다. 같은 장비의 압축기 두 대가 TLC 하나를 함께 쓰는 것으로 확인되면, 두 행에 같은 MAC·IP를 적고 비고란에 그 사실을 남긴다.

## 3. IP를 받은 뒤 반영 방법

반영할 곳은 두 군데다. **CSV를 꼭 함께 고쳐야 한다** — 납품 초기화(`Infrastructure/Setup/reset_for_delivery.sql`)와 새 서버 설치가 CSV로 만든 seed를 다시 넣기 때문이다. DB만 고치면 그때 IP가 지워진다.

1. **장비 자료(CSV)**
   - `Infrastructure/Compressors.csv`에서 압축기ID(첫 번째 열 `id`)가 같은 행의 `IpAddress`, `MacAddress` 열을 채운다.
   - 저장소 루트에서 `node Infrastructure/Seed/generate_seed_from_csv.js`를 실행해 `seed_from_csv.sql`을 다시 만든다.
2. **운영 중인 DB**
   - 화면의 압축기 정보 수정이나 `PUT /api/compressors/{id}`(api-manual.md 24번)로 IP와 MAC을 입력한다.
   - 입력하면 다음 폴링 주기(3초)부터 바로 수집 대상이 된다. 서버를 재시작하지 않아도 된다.

반영한 뒤에는 `Infrastructure/Setup/check_install.sql`의 `[통신 상태]` 항목이나 화면에서 해당 장비가 `연결됨`으로 바뀌는지 확인한다. 테스트 모드에서는 모의값이라 확인이 안 되므로, 실제 통신 모드에서 확인한다.
