# Trend 모듈

트렌드(DailyTrend) 기록 모듈. 원래 이름은 History였으나, 실제 역할이 "1분 단위 센서 트렌드 저장·조회" 하나뿐이라
overview.md 전체에서 쓰는 용어(트렌드, DailyTrend)에 맞춰 이름을 바꿨다. 경보 이력/비상정지 이력/시스템 이벤트 로그는
각각 Alarm/EmergencyStop/Logging 모듈 소관이라 이 모듈과 무관하다.

- 압축기별 7채널 센서 정보 1분 단위 저장 (정각 기준)
- 운전 상태, 경보 상태, 통신 상태 포함 저장
- 압축기별/채널별/날짜별 트렌드 조회

## 내부 구성 (예정)

- `Models/` — CompressorMeasurement 엔티티
- `Services/` — 1분 정각 스케줄러, 저장 로직
- `Controllers/` — 트렌드/이력 조회 API

## 데이터 사용량

`CompressorMeasurement`는 압축기 1대당 1분에 1행씩 계속 누적되는 테이블이라, 시간이 지날수록 커진다. 실제로 압축기 244대 전체 기준 하루치(351,360행)를 채워서 측정한 결과:

| 기간 | 용량(테이블+PK 인덱스) |
|---|---|
| 하루 | 약 52MB |
| 한 달(30일) | 약 1.5GB |
| 1년(365일) | 약 18.4GB |

- 통신 이력이 한 번도 없는 압축기는 채널값이 NULL로 기록되므로, 실제 운영 중에는 이 수치보다 약간 적게 나온다(위 수치는 안전한 상한).
- PostgreSQL 기준으로 이 정도 크기는 부담스러운 수준이 아니라서, 지금 단계에서 파티셔닝이나 별도 아카이빙은 하지 않는다.
- 데이터 보관 기간·백업 정책·장기 파티셔닝 전략은 [overview.md 12장](../../Doc/overview.md#12-추후-결정-필요사항)에 "추후 결정"으로 남아있다. 수 년치가 쌓여 수백 GB 단위가 되는 시점에 다시 검토한다.
