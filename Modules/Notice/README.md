# Notice 모듈 (공지사항)

전사 공지사항. **결재가 없는 가장 단순한 문서 모듈**이다 — 교육훈련 일지(`Modules/TrainingLog`)에서 결재만 빼면 사실상 같은 구조다.

당초 사양에 있던 **자유게시판 기능은 2026-09-16에 사양에서 완전히 제거되고 이 공지사항으로 통합**됐다(사용자 결정). 그에 따라 초기 게시판 사양의 조회수·공개 범위 항목도 사양에서 빠졌고, 껍데기만 남아 있던 `Modules/Reports` 폴더도 이때 삭제했다(교육훈련은 `TrainingLog`, 공지사항은 이 모듈, 첨부파일은 `Attachment`로 전부 이관 완료된 상태였다).

## 내부 구성

- `Controllers/NoticesController.cs` — 조회/등록/수정/삭제 + 상단 고정/해제 API
- `Models/Notice.cs` — 엔티티
- `Models/Dtos.cs` — 요청/응답 DTO

## 데이터 요소

| 한글명 | 필드 | 타입 | 비고 |
| --- | --- | --- | --- |
| 제목 | `Title` | `string` | 필수 |
| 내용 | `Content` | `string?` | |
| 상단 고정 | `IsPinned` | `bool` | **시스템관리자만** 변경 가능(전용 엔드포인트) |
| 작성자 / 작성일시 | `CreatedByUserId` / `CreatedByUserName` / `CreatedAt` | | 자동 기록 |
| 수정자 / 수정일시 | `UpdatedByUserId` / `UpdatedByUserName` / `UpdatedAt` | | 수정 시 자동 기록 |

초기 프론트 화면 사양에 적혀 있던 "작성자, 날짜"는 사용자 입력 필드가 아니라 시스템이 자동으로 남기는 값으로 해석했다(응답의 `createdByUserName`/`createdAt`). 사용자가 입력하는 필드는 제목·내용 둘뿐이다.

## 상단 고정 (`IsPinned`)

- 목록 조회는 **고정 공지 우선 → 그 다음 작성일시 내림차순**으로 정렬된다(`OrderByDescending(IsPinned).ThenByDescending(CreatedAt)`).
- **시스템관리자만** 설정/해제할 수 있다. 그래서 일반 수정(`PUT`)의 요청 본문에는 `isPinned`가 아예 없고, 전용 엔드포인트(`POST {id}/pin`, `POST {id}/unpin`)로만 바꾼다 — 작성자가 본문을 수정할 때 고정 상태가 함께 바뀌는 일을 구조적으로 막기 위함이다.
- 고정 가능 여부를 알려주는 응답 필드는 따로 두지 않았다. 조건이 "시스템관리자인가" 하나뿐이고, 그건 로그인 응답의 `role`로 프론트가 이미 알 수 있다.

## 권한 규칙 (사용자 결정)

| 동작 | 권한 |
| --- | --- |
| 조회 | 로그인한 사용자 누구나 |
| 등록 | 로그인한 사용자 누구나 |
| 수정 | 작성자 또는 시스템관리자 |
| 삭제 | 작성자 또는 시스템관리자 |
| 상단 고정/해제 | 시스템관리자만 |
| 첨부파일 추가/삭제 | 작성자 또는 시스템관리자(= 수정 권한과 동일) |

`CanEdit`/`CanDelete`는 이 표를 요청자 기준으로 계산해 응답에 담는 값이다(응답 전용, 프론트 버튼 표시용). 수정과 삭제의 조건이 같아서 두 값은 항상 같지만, 프론트가 버튼별로 쓰기 편하도록 따로 내려준다.

## 첨부파일

`Modules/Attachment`를 `ownerType=Notice`, `ownerId=이 레코드의 Id`로 사용한다. 슬롯 없이 다건(파일마다 새 행), 확장자 제한 없음, 파일당 최대 10MB(공통 규칙). 공지를 삭제하면 이 컨트롤러가 딸린 첨부파일(파일+DB행)을 함께 정리한다.

첨부 추가/삭제 권한은 **문서 수정 권한과 동일**하게 작성자 또는 시스템관리자로 제한된다 — 첨부 변경도 결국 공지 내용 변경이기 때문이다. 이 검사는 `AttachmentsController.CheckDocumentOwnerAsync`가 `Notices`의 `CreatedByUserId`를 조회해서 수행한다.

## 사양 이슈 / 결정 이력

- **제목 필드 추가(2026-09-16)**: 초기 프론트 화면 사양에는 제목이 없었으나(작성자/날짜/내용/첨부파일) 실제 사양에 제목이 추가되어 문서를 갱신했다.
- **편집/삭제 사양 확정(2026-09-16)**: 문서에는 "조회 / 등록"만 적혀 있어 편집·삭제 권한이 미정이었다. "작성자 또는 시스템관리자"로 확정했다.
- **상단 고정 기능 추가(2026-09-16)**: 최초 사양(제목·내용)에는 없었으나 요청으로 추가됐다. 관리자 전용이며 전용 엔드포인트로 분리했다.
- **첨부 권한 일관화(2026-09-16)**: 원래 `Attachment` 모듈은 문서형 첨부를 "로그인한 누구나" 변경 가능하게 처리하고 있었는데, 그러면 "수정은 작성자만"이라는 규칙에 구멍이 생긴다(남의 공지에 아무나 파일을 붙이거나 뗄 수 있음). 이 문제를 공지사항뿐 아니라 **장비 검사이력·교육훈련 일지까지 함께 고쳤다**(사용자 결정) — 상세는 [Modules/Attachment/README.md](../Attachment/README.md).
