# TrainingLog 모듈 (교육훈련 일지)

안전 교육/훈련 실시 내역을 기록하고 결재를 받는 모듈. 다른 결재 문서(점검일지/운전일지/수리일지)와 달리 **장비에 매달리지 않는 전사 문서**다.

## 내부 구성

- `Controllers/TrainingLogsController.cs` — 조회/등록/수정/삭제 + 결재(승인/취소/리셋) API
- `Models/TrainingLog.cs` — 엔티티(데이터 6필드 + 작성자/수정자 + 결재 인라인 컬럼 9개)
- `Models/Dtos.cs` — 요청/응답 DTO

## 데이터 요소

| 한글명 | 필드 | 타입 | 필수 |
| --- | --- | --- | --- |
| 제목 | `Title` | `string` | 필수 |
| 일시 | `PerformedAt` | `DateTimeOffset` | 필수 |
| 장소 | `Location` | `string?` | |
| 강사 | `Instructor` | `string?` | |
| 교육내용 | `Content` | `string?` | |
| 참석자 명단 | `Attendees` | `string?` | **단순 문자열** — 시스템 등록 인원(`Users`)과 무관 |

`EquipmentId`가 없다. 목록 조회도 필터 없이 전체를 `PerformedAt` 내림차순으로 반환한다(연간 몇 건 수준이라 기간 필터·페이징을 두지 않았다 — 사용자 결정).

## 결재 사양

`Modules/Approval`의 공용 규칙(`ApprovalRules`)을 재사용한다. 레벨별 모드는 수리일지와 동일하다.

| 레벨 | 역할 | 모드 | 프론트 표시 |
| --- | --- | --- | --- |
| 1 | 안전관리원 | `NotApplicable`(해당없음) | `/` |
| 2 | 안전관리책임자 | `Required` | 대기 / 승인자명 |
| 3 | 안전관리총괄자 | `Required` | 대기 / 승인자명 |

**이 모듈만의 예외 — 승인 시 담당 장비를 검사하지 않는다.** 다른 결재 문서는 "호출자의 역할 + 그 장비의 담당자(`UserEquipment`)"를 함께 확인하지만, 교육훈련은 검사할 장비가 없어 **역할만으로 승인 권한을 판정한다**(사용자 결정). 즉 안전관리책임자/안전관리총괄자면 누구나 승인할 수 있다. 같은 이유로 `EventLog`에도 `equipmentId`를 남기지 않는다.

나머지는 공용 규칙 그대로다 — 순서 강제(레벨1이 `NotApplicable`이라 책임자가 첫 승인자), 취소는 본인 단계만·상위 미승인 시에만, 반려 없음, 시스템관리자는 승인 불가·리셋만 가능, 승인/취소/리셋은 `EventLog`(Approval 카테고리) 기록.

## 권한 규칙 (수리일지와 동일 — 사용자 결정)

| 동작 | 결재 진행 전 | 결재가 1건이라도 승인된 후 |
| --- | --- | --- |
| 조회 | 로그인한 사용자 누구나 | 동일 |
| 등록 | 로그인한 사용자 누구나 | — |
| 수정 | 시스템관리자 또는 작성자 | **누구도 불가** (`409`) |
| 삭제 | 시스템관리자 또는 작성자 | **시스템관리자만** (`403`) |
| 첨부파일 추가/삭제 | 시스템관리자 또는 작성자 | **누구도 불가** (`409`) |

`CanEdit`/`CanDelete`는 이 표를 요청자 기준으로 계산해 응답에 담는 값이다(응답 전용, 프론트 버튼 표시용).

## 첨부파일

`Modules/Attachment`를 `ownerType=TrainingLog`, `ownerId=이 레코드의 Id`로 사용한다. 슬롯 없이 다건(파일마다 새 행), 확장자 제한 없음(교육자료는 PDF·문서·이미지가 섞인다), 파일당 최대 10MB(공통 규칙).

- 문서를 삭제하면 이 컨트롤러가 `AttachmentStorage`를 직접 호출해 딸린 첨부파일(파일+DB행)을 함께 정리한다.
- **첨부 추가/삭제 권한은 문서 수정 권한과 동일**하게 작성자 또는 시스템관리자로 제한된다(2026-09-16 추가 — 처음에는 로그인한 누구나 가능했는데, 수정 권한과 어긋나는 구멍이라 공지사항 작업 중 함께 정리했다).
- **결재가 진행되면 첨부파일 추가/삭제도 막힌다**(`409`). 첨부 변경도 문서 내용 변경이라 "결재 후 수정 불가" 규칙을 함께 적용해야 하기 때문이다. 이 검사는 `AttachmentsController`가 `TrainingLogs`의 결재 상태를 직접 조회해서 수행한다 — 도메인에 무관하게 동작하는 Attachment 모듈의 의도적인 예외이며(`EquipmentPhoto`가 `EquipmentAccess`를 쓰는 것과 같은 성격), `Modules/Attachment/README.md`에도 기록돼 있다.

## 사양 이슈 / 결정 이력

- **제목 필드 추가(2026-09-16)**: 초기 프론트 화면 사양에는 제목이 없었으나(일시/장소/강사/교육내용/참석자/첨부파일), 실제 사양에 제목이 추가되어 문서를 갱신했다.
- **결재 권한 판정 방식(2026-09-16)**: 장비와 무관한 문서라 담당 장비 검사를 생략하고 역할만 보기로 결정했다. 이로써 `Modules/Approval/README.md`의 "승인은 Role + 담당장비 기준" 문구가 모든 문서에 해당하지 않게 되어, 해당 README도 함께 갱신했다.
- **목록 조회 방식(2026-09-16)**: 기간 필터(`from`/`to`)를 둘지 검토했으나, 건수가 적어 전체 반환만 제공하기로 결정했다(단순함 우선).
- **`PerformedAt`은 UTC로 정규화 저장**: Npgsql이 `timestamptz` 컬럼에 offset 0(UTC)인 `DateTimeOffset`만 허용해서, 프론트가 한국시간 오프셋(`+09:00`)으로 보내면 그대로 쓰면 500이 난다. 수리일지 구현 중 실제로 발생해 잡은 이슈이며 같은 방식으로 처리한다(시점은 보존, 응답도 UTC).
