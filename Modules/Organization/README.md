# Organization 모듈 (조직관리)

사용자(안전관리 담당자) 등록·조회·수정·비활성화 API. 사용자 엔티티 자체(`User`, `UserEquipment`, `UserRole`)는 로그인과 함께 쓰이므로 `Modules/Auth`에 두고, 이 모듈은 그 데이터를 관리하는 API만 갖는다.

## 내부 구성

- `Controllers/UsersController.cs` — 조직관리 API (`/api/users`)
- `Models/Dtos.cs` — 요청/응답 DTO

| 한글명 | 필드 | 타입 | 비고 |
| --- | --- | --- | --- |
| 사용자 ID | `Username` | `string` | 필수, 유니크(비활성 계정 포함). **생성 후 변경 불가**. 등록 전 중복확인 API 제공 |
| 비밀번호 | `PasswordHash` | `string` | `PasswordHasher`로 해시 저장. 응답에 절대 포함하지 않음 |

| 소속팀 | `Department` | `string?` | |

| 담당업무 | `Role` | `UserRole` | 안전관리총괄자/안전관리책임자/안전관리원/일반관리원 — **결재 권한과 같은 값** |

## 담당업무 = 권한(Role)

담당업무는 별도 필드가 아니라 기존 `Role`을 그대로 쓴다(사용자 결정 2026-09-17). 따라서 **담당업무를 바꾸면 결재 가능 단계도 함께 바뀐다**(`ApprovalRules.LevelForRole`: 안전관리원=1, 안전관리책임자=2, 안전관리총괄자=3, 일반관리원=결재 대상 아님).

- 기존 역할명 `일반관리자`는 사양 표기에 맞춰 **`일반관리원`으로 이름을 바꿨다.** DB에는 순번(정수)으로 저장돼 마이그레이션은 필요 없었다. 다만 이름이 바뀌기 전에 발급된 로그인 토큰의 역할 문자열은 옛 이름이라, 해당 역할 사용자가 있었다면 재로그인이 필요하다(변경 시점에 해당 역할 사용자는 없었다).
- **시스템관리자는 담당업무가 아니다.** 별도 관리 계정으로 취급해서 이 API로는 지정할 수 없고(`400`), 조직 목록에서도 빠지며, 이 API로 수정·비활성화·비밀번호 초기화할 수도 없다(`404`). 관리자 계정이 실수로 잠기는 것을 막는 효과도 있다. 관리자 본인의 비밀번호 변경은 `/me/password`로 가능하다.

## 권한 규칙 (사용자 결정)

| 동작 | 권한 |
| --- | --- |
| 목록·상세 조회 | 로그인한 누구나 |
| 본인 정보 조회(`/me`) | 로그인한 누구나(시스템관리자 포함) |
| ID 중복확인, 등록, 수정, 비밀번호 초기화, 비활성화/활성화 | 시스템관리자만 |
| 본인 비밀번호 변경(`/me/password`, 현재 비밀번호 확인 필요) | 본인 |
| 본인 연락처 변경(`/me/contact`) | 본인 — 본인이 바꿀 수 있는 인적사항은 연락처1·2뿐 |
| 선해임 신고서 업로드·삭제 | 시스템관리자만 |

조회를 로그인한 누구나로 둔 것은 조직도·연락처가 내부 업무에 필요하다고 봤기 때문이다(비밀번호 해시는 어떤 응답에도 포함되지 않는다). 제한이 필요하면 `GetList`/`GetOne`에 역할 조건만 추가하면 된다.

## 삭제 대신 비활성화

삭제 API는 없다. `IsActive=false`로 바꾸면 로그인만 막히고 계정·담당장비·신고서 기록은 그대로 남는다. 점검일지 등의 결재자·작성자 이름은 원래부터 기록 시점의 이름 스냅샷이라 영향이 없다.

**주의 — 비활성화해도 이미 발급된 로그인 토큰은 만료(12시간)까지 유효하다.** 토큰을 서버가 무효화하지 않는 현재 인증 구조(`Modules/Auth`) 때문이다. 즉시 차단이 필요해지면 요청마다 `IsActive`를 확인하는 처리를 인증 쪽에 추가해야 한다.

## 담당장비 수정 방식

`PUT /api/users/{id}`의 `equipmentIds`는 **목록 전체 교체**다(보낸 목록에 없는 장비는 담당에서 빠지고, 새로 들어온 장비는 추가). 중복 Id는 자동으로 하나로 정리되고, 존재하지 않는 장비 Id가 섞이면 `400`.

## 선해임 신고서

`POST /api/attachments?ownerType=AppointmentReport&ownerId={사용자Id}`로 올린다. 사용자당 1건이라 서버가 슬롯을 `report`로 고정하고, 다시 올리면 기존 파일을 교체한다(첨부 Id 유지). 확장자 제한 없음, 파일당 10MB. 사용자 응답의 `appointmentReportId`로 존재 여부와 다운로드 Id를 바로 알 수 있다.
