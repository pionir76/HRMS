# Alarm 모듈

경보 처리 모듈.

- 채널별 상한/하한 범위 판정
- 경보 발생 지연시간 / 해제 지연시간 처리
- 경보 상태 머신 (정상/경보발생대기/경보발생/정상복귀대기/경보비활성화)

히스테리시스, 경보 확인/해제 상태는 사양에서 제외됐다. 통신 장애 경보(`Compressor.HasCommunicationAlarm`)는 이 모듈이 아니라 `CompressorPollingService`가 관리한다.

## 내부 구성

- `AlarmEvaluator.cs` — 채널 하나의 경보 상태 전이 판정
- `Models/AlarmStatus.cs` — 경보 상태 enum

## `hasAlarm` 판정 — 확정된 경보만 true (사용자 결정 2026-09-17)

API와 트렌드 기록의 `hasAlarm`은 `AlarmStatusExtensions.IsConfirmedAlarm()` 한 곳에서 계산한다.

| 상태 | `hasAlarm` |
|---|---|
| `경보발생` | true |
| `정상복귀대기` | true — 범위 안으로 돌아왔지만 해제 지연시간을 아직 못 채워 경보가 유지 중 |
| `경보발생대기` | false — 범위를 벗어났지만 발생 지연시간을 아직 못 채움(미확정) |
| `경보비활성화` | false |
| `정상` | false |

이전에는 "정상이 아니면 true"라서 경보발생대기·경보비활성화도 경보로 표시됐다. 수정 전에 기록된 트렌드(`CompressorMeasurement.HasAlarm`)는 옛 기준 그대로 남아 있다.

## 통신이 끊긴 압축기의 경보 — 해제한다 (사용자 결정 2026-09-28)

값을 읽을 수 없는 동안에는 경보 여부를 알 수 없으므로 **"모르면 경보 아님"** 으로 본다. 통신에 실패한 압축기의 모든 채널을 `정상`으로 내리고 대기 타이머도 지운다.

그 전에는 판정에서 건너뛰기만 해서(옛 상태 유지) 이런 문제가 있었다 — 압축기 2대짜리 장비에서 1번이 `경보발생` 상태로 끊기고 2번이 계속 운전 중이면, 장비는 운전 중이라 "비운전이면 전부 정상" 분기를 타지 않고, 끊긴 1번의 경보가 얼어붙어 **장비 경보로 무기한 집계**됐다.

- **해제 이벤트는 남기지 않는다** — 비운전 처리와 같은 원칙이다(발생만 있고 해제가 없는 이벤트가 생길 수 있다).
- **통신이 복구되면 `정상`에서 다시 판정한다.** 값이 여전히 범위 밖이면 발생 지연시간(기본 30초)을 다시 채운 뒤에 경보가 확정된다(의도된 동작).
- 통신 두절 자체는 별도의 **통신 장애 경보**(`HasCommunicationAlarm`, 30초 지속 시)로 알린다. 화면에서는 `communicationStatus`가 `끊김`인 것을 우선 표시하면 "정상"과 "알 수 없음"이 구분된다.

## 판정 전제: 장비가 운전 중일 때만 판정 (사양 변경 2026-09-17)

`AlarmEvaluator`는 **소속 장비가 운전 중(`Equipment.IsRunning`)인 채널에만 호출된다.** 호출 여부는 `CompressorPollingService.EvaluateAlarmsAsync`가 정한다.

- 장비가 운전 중이 아니면 그 장비의 모든 압축기·모든 채널을 무조건 `정상`으로 두고 `PendingSince`도 지운다. **경보 이벤트(발생·해제 모두)를 남기지 않는다.**
  - 압축기 1번이 `경보발생`이었어도 장비가 정지하면 즉시 `정상`이 된다. 그래서 이벤트 이력에 발생만 있고 해제가 없는 경보가 생길 수 있다 — 사양상 의도된 것이다.
  - 설정상 `경보비활성화`인 채널도 비운전 중에는 `정상`으로 표시된다("무조건 정상").
  - 다시 운전을 시작하면 `정상`에서 판정을 새로 시작하므로, 범위를 벗어나 있어도 발생 지연시간을 다시 채워야 경보가 된다.
- 운전 판정은 경보 판정보다 먼저, 같은 사이클의 값으로 한다(`EquipmentStatusAggregator.UpdateRunningAsync`). 운전전류 임계값이 없는 장비와 통신이 끊긴 장비는 정지로 판정되므로 경보 판정도 하지 않는다.
- 통신 장애 경보는 이 전제와 무관하다 — 통신이 끊기면 운전 판정이 정지가 되므로, 여기에 묶으면 통신 장애 경보가 절대 뜰 수 없다.
