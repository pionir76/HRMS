# EquipmentInspectionHistory 모듈

장비 이력카드에서 장비별 검사/점검 이력을 자유 서술형으로 등록/조회/편집/삭제하는 모듈. **기존 `Modules/InspectionReport`(점검일지 — 매주 고정 10항목 체크리스트 + 3단계 결재)와는 완전히 별개**다. 이름이 비슷해서 혼동하기 쉬우니 주의.

> 사양 변경 이력
> - 2026-09-14: 삭제를 시스템관리자 전용으로 제한
> - 2026-09-16: 수정을 시스템관리자 또는 작성자 본인으로 제한(그 전에는 로그인한 누구나 수정 가능)
> - 2026-09-16: 첨부파일 추가/삭제도 같은 조건(시스템관리자 또는 작성자)으로 제한 — 공지사항 작업 중 "수정은 작성자만인데 첨부는 누구나"라는 구멍이 발견되어 함께 정리함

## 내부 구성

- `Controllers/EquipmentInspectionHistoryController.cs` — 등록/조회/편집/삭제 API
- `Models/EquipmentInspectionHistory.cs` — 엔티티
- `Models/Dtos.cs` — 요청/응답 DTO

## 설계 결정 (사용자 결정)

- **결재 없음.** `Doc/Front_Work.md` 7장에도 같은 절의 "수리보수일지"만 결재 시스템이 언급되고 "검사 이력"은 등록/조회/편집만 명시되어 있다.
- **담당 장비 제약 없음.** 장비관리(`Equipment`/`Compressor`/채널설정)와 달리 `EquipmentAccess`를 쓰지 않는다 — 어느 장비의 이력이든 장비 담당자 여부와 무관하게 접근한다. 대신 아래 권한 규칙이 적용된다.
- **동작별 권한 규칙** (전부 사용자 결정):

| 동작 | 권한 | 비고 |
| --- | --- | --- |
| 조회(`GET`) | 로그인한 사용자 누구나 | |
| 등록(`POST`) | 로그인한 사용자 누구나 | |
| 수정(`PUT`) | 시스템관리자 **또는 작성자 본인**(`CreatedByUserId`) | 2026-09-16 변경 — 그 전에는 누구나 수정 가능했음. 위반 시 `403`. 조회 응답의 `CanEdit`이 이 조건을 그대로 계산한 값이다 |
| 첨부파일 추가/삭제 | 시스템관리자 **또는 작성자 본인** | 2026-09-16 변경 — 그 전에는 누구나 가능했음(수정 권한과 어긋나는 구멍이었다). `AttachmentsController`가 판정 |
| 삭제(`DELETE`) | 시스템관리자만 | 2026-09-14 결정. `[Authorize(Roles = ...)]`로 처리 |

- **`CanEdit`은 응답 전용 계산 필드.** 프론트가 수정 버튼 표시 여부를 판단할 때 쓰도록, 위 "수정" 권한 조건을 서버가 요청자 기준으로 계산해서 DTO에 같이 담는다. 그래서 `ToDto`는 `static`이 아니다(요청자 정보가 필요함).
- **삭제 API가 존재한다.** 이 시스템의 다른 데이터(장비, 점검일지, 운전일지 등)는 대부분 "삭제 없음, 이력 보존" 원칙이지만, 이 모듈은 사용자 결정으로 `DELETE`를 명시적으로 열어뒀다(원칙의 예외).
- **`EquipmentId`는 생성 후 불변.** 다른 장비로 이력을 옮기는 시나리오는 없다고 보고 `PUT` 요청에서 아예 뺐다.
- **주/일 단위 유니크 제약 없음.** 점검일지·운전일지와 달리 장비 하나에 이력이 몇 건이든 자유롭게 쌓인다(로그성 데이터).

## 첨부파일

이 모듈은 첨부파일을 직접 갖지 않는다 — [Modules/Attachment](../Attachment/README.md)를 `ownerType=EquipmentInspectionHistory`, `ownerId=이 레코드의 Id`로 사용한다. 슬롯 개념 없이 다건 첨부(파일마다 새 행), 확장자 제한 없음(장비 사진과 달리 문서 파일 등도 허용), 파일당 최대 10MB는 공통 규칙 그대로 적용된다.

이력 자체를 삭제(`DELETE /api/equipment-inspection-history/{id}`)하면 컨트롤러가 `AttachmentStorage`를 직접 호출해서 딸린 첨부파일(파일+DB행)을 함께 정리한다 — 고아 파일이 남지 않게.
